# Phase 07 — Timeline and training table

**Goal.** One BigQuery table where each row is a (channel, video, audience, bin) with its full feature vector and the measured hazard as the label. The TypeScript featurizer in `packages/core` computes every column, including the spline basis and interaction terms, so the Python fitter only ever reads a finished matrix and live predictions use exactly the same code.

**Depends on.** Phases 04 and 06. Day: Oct 6.

## Stack

- TypeScript in `packages/core/src/features`; columns as `Float64Array` (no dataframe library needed)
- `@google-cloud/bigquery` (NDJSON load jobs)
- Vitest and fast-check; one fixture generated by Python for the spline cross-check

## Build

1. `features/timeline.ts`: `buildBins(video: VideoBeats, durationS, channelCtx, mix) -> FeatureFrame`, where `FeatureFrame` is 100 rows by `FEATURE_SPEC.length` columns stored column-major. Bin i covers `[(i-1)/100 * D, i/100 * D)`. Every feature is overlap-weighted across the beats that intersect the bin.
2. Feature families:
   - **Beat type shares:** fraction of the bin covered by each `beat_type`.
   - **Framing shares:** fraction by each `framing` value.
   - **Visual and audio:** `cuts_per_min` (weighted mean), `on_screen_text` share, `music_bg` and `music_fg` shares, `silence` share (beats with empty transcript).
   - **Delivery:** `energy`, `assumed_knowledge`, `info_density` (weighted means), `speech_wpm` (transcript words spread evenly across each beat).
   - **Dynamics:** `secs_in_current_beat` at the bin midpoint; `static_run_s` (consecutive seconds of `talking_head_static` up to the midpoint, crossing beat boundaries); `energy_delta` versus the previous bin.
   - **Narrative:** `open_loops` (opened and not yet closed at the midpoint); `before_payoff`; `knowledge_gap` = `assumed_knowledge` minus the channel's median `target_level`.
   - **Position:** `is_first_bin`, `log_bin_seconds` (D/100), `log_duration`, and `pos_b1` to `pos_b6`: a cubic B-spline basis of elapsed ratio with interior knots at 0.25, 0.5 and 0.75, implemented with the Cox–de Boor recursion in `features/spline.ts`. Knots live in the spec.
   - **Video level:** `format` one-hot, `target_level`.
   - **Audience mix and interactions (newcomer rows only; zero elsewhere):** `search_share`, `suggested_share`, `browse_share` within non-subscribers, each centered at the channel mean stored in `channelCtx`; plus explicit interaction columns `ix_<feature>_<mix>` for the 6 content features named in Phase 08. Computing interactions here keeps the model purely linear in the feature vector.
3. `features/spec.ts`: `FEATURE_SPEC`, an ordered list of `{name, kind, clip}` plus the spline knots. It is the single source of truth for column order. A test asserts `FEATURE_VERSION` equals a hash of the spec, so changing features without bumping the version fails CI.
4. Leakage list in the same module: views, average view duration, `rewatch_mass`, `relativeRetentionPerformance`, anything derived from analytics. A test asserts none of them is in the spec.
5. `apps/pipeline/src/commands/features.ts`: for each video and audience in `all`, `subscribed`, `unsubscribed`, join bins to hazards by bin index. Compute `n_at_risk` = views for that audience times `s_mono[i-1]` (with `s_mono[0]` = 1). Write `training_bins` rows: `channel_id`, `video_id`, `audience`, `bin`, `hazard`, `n_at_risk`, `video_views`, `feature_version`, and `x` as `ARRAY<FLOAT64>` in spec order. Also write the spec itself to a `feature_specs` table keyed by version, so Python can name columns. Partition by channel, cluster by video.
6. EDA lives in Python, where plotting is easy: `services/modeling/src/soundcheck_modeling/eda.py` reads `training_bins` and `feature_specs` and writes rows per channel and audience, missingness, distributions and each feature's correlation with hazard to `docs/eda/`.
7. Tests:
   - Golden test: a hand-made 3-beat video with known expected bin values.
   - Property tests: beat-type shares sum to 1 per bin; the full B-spline basis (with intercept) sums to 1 at every point.
   - Spline cross-check: `services/modeling/scripts/spline_fixture.py` writes basis values from `scipy.interpolate.BSpline` for 101 points to `tests/fixtures/spline.json`; the TypeScript basis must match within 1e-12.
   - Leakage test and determinism test (same input, byte-identical frame).

## Decisions and gotchas

- Bins are relative, so a 40-minute video has 24-second bins and a 5-minute video 3-second bins. `log_bin_seconds` lets the model compare hazards across videos.
- Bin 1 carries packaging effects (title and thumbnail mismatch). `is_first_bin` absorbs them so content features are not blamed.
- Storing `x` as an array keyed by spec version means adding a feature never needs a BigQuery schema migration.

## Do not

- Compute any feature in Python.
- Use any outcome-derived value as a feature.
